# P1.2 状态转换验收

日期：2026-11-07

## 结论

P1.2 已完成。本卡只验收流程状态、异常终止和诊断模式记录；没有调整夹具、默认送料/退出动作或质量阈值。

| 场景 | 结果 | 证据 |
|---|---|---|
| 正常全物理送料，D=25 mm | PASS，`execution_status=completed` | `_build/p12_normal.json` |
| D=8 mm 质量不达标 | `FAIL`，仍是 completed case，原因 `stock_eccentricity` | `_build/p12_quality_fail.json` |
| `dy=+50 mm` 抓空 | `ABORT`，`abort_stage=grasp`，接触数 0；未继续到卡盘闭合 | `_build/p12_grasp_abort.json` |
| 松爪后不移动诊断 | `diagnostic_mode=stationary_after_release`，有效配置 `retreat_axial=false` | `_build/p12_stationary.json` |
| 取消轴向退出诊断 | `diagnostic_mode=no_axial_retreat`，有效配置 `retreat_axial=false` | `_build/p12_no_axial.json` |
| 运行时 NaN，在步骤前检查 | 写出 `execution_status=error`，在下一仿真步前终止 | `_build/p12_nan_runtime.json` |
| 运行时 NaN，在 `mj_step` 后注入 | 写出 `execution_status=error`，在该仿真步后终止 | `_build/p12_nan_step.json` |
| 扫描器收到 error JSON | CSV 标为 `ERROR`，保留原因与阶段 | `_build/p12_scanner_error.json` |
| 子进程没有写出 JSON，且目标路径原有旧 PASS | 旧文件先被清除，CSV 标为 `ERROR` | `_build/p12_stale.json` |

三个结果分类不混淆：质量门槛未通过仍为 `FAIL`；预期抓取中止为 `ABORT`；数值异常和扫描结果缺失为 `ERROR`。扫描器先删除同名旧 JSON，避免把上次运行结果误当成当前结果。

## 实现范围

- `src/diag_feed_chuck.py`：每个仿真步前后检查仿真时间、`qpos`、`qvel`、`ctrl`、`qacc`、`qfrc_applied` 和 `xfrc_applied`；非有限值会写 ERROR JSON 并以 `FloatingPointError` 终止。阶段记录执行 `mj_forward` 后也复查。
- 抓取无接触分支写入 `execution_status=aborted`、`abort_stage`、失败标签及当时配置/指标。
- 完成结果显式写入 `execution_status=completed` 和抓取接触数。
- 诊断 JSON 记录实际生效的退出配置，避免“松爪后不移动”仍被记录为轴向退出开启。
- `src/diag_feed_insert_sweep.py`：输出 execution status、diagnostic mode 与 abort stage；异常 JSON 或缺失结果保持 ERROR，不会映射成质量 FAIL 或 PASS；运行前删除旧 JSON。

## 复现

```powershell
$env:PYTHONIOENCODING = "utf-8"
& .venv\Scripts\python.exe -m py_compile src\diag_feed_chuck.py src\diag_feed_insert_sweep.py
& .venv\Scripts\python.exe verify_all.py
```

针对性分支通过 `_build/p12_*.json` 进行验收；两种 NaN 注入均由短 Python harness 调用同一 `main()`，一条在活动帧回调注入，一条在 `mj_step` 返回后注入。

完整回归：`verify_all.py` **9/9**。正常全物理基准余量偏心 0.70/2.0 mm；D=8 mm 保持原有质量 FAIL，余量偏心 2.28 mm 左右。

## 边界与后续

- 本卡证明了定义的仿真状态分支可正确记录和终止，不等于完成所有异常物理工况的覆盖。
- `_build` 下的 JSON 是本地验收证据，不作为跨机器长期存档；正式实验数据规范属于后续 P2。
- 后续故障分类见 [P1.4 验收](p1.4-failure-detection-2026-11-07.md)：已验证受控碰撞检测；本轮 P1.2 本身仍未实现不可达专用判据，也不把高 IK 残差单独宣称为不可达。
