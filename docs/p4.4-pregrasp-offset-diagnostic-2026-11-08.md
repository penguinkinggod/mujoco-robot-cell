# P4.4 补充：抓取前偏移保留诊断

完成日期：2026-11-08

## 为什么补这一项

P4.4 的请求偏移在抓取前经过 600 个仿真步静置。已有结果显示 V 槽和导套会把小偏移基本消掉，因此 P4.4 不能单独回答“机械臂能否从仍然偏着的位置抓取”。

本诊断只改变初始扰动后的静置步数，原送料动作、工装、插入深度和 PASS/FAIL 判据不变。新增入口 `--initial-settle-steps` 默认仍为 600；设为 0 表示扰动后不先运行静置步，立即开始机械臂流程。该模式是诊断，不替代真实输送带/传感器模型。

## 固定工况

- 工件：Ø20 × 80 mm 圆柱。
- 工装：当前 90° V 槽、托架和导套。
- 插入深度：25 mm。
- 主偏移：`dy=+3 mm`、`dz=+2 mm`、world-Z `yaw=+5°`。
- M0：固定名义抓取目标。
- M1：使用机器人开始接近前读取的仿真真值规划抓取目标。
- 搬运不使用运动学锁，维持 P4.4 主物理送料模式。
- 另对 M1 分别测了 `dy=+3 mm`、`dz=+2 mm`、`yaw=+5°` 单轴工况，均为 0 步静置。

## 结果

|---:|---|---|---|---|

| 600 | M1 | `(260.736,-130.000,39.815) mm`，yaw 约 `0°` | PASS | 余量偏心 `1.520 mm` |

## 怎么理解

1. 0 步时，M0 的圆柱起点确实偏了；第一段机械臂接近结束时，圆柱已回到接近名义位置，但此时夹爪离工件约 84 mm，尚未接触。更合理的解释是支撑结构在机械臂移动所经过的时间里继续自定心，不能归因为夹爪把工件推正。
2. M1 的抓取目标按接近开始前的真值重算，但圆柱在机械臂移动期间继续自定心，目标可能因此过时。M1 横移/偏航工况失败，可能与目标变旧、V 爪姿态或机械臂可达性限制有关；单凭这些样本不能确定唯一根因。
3. 高度单轴通过、横移和偏航单轴失败，是下一轮值得追查的差异；每种只有一个正向样本，不能外推到负方向或整个范围。
4. 约 3 mm 的 V 爪接触穿透在 0 步与 600 步对照中都出现，量级接近；本诊断不把它当成 0 步新引入的独立失败。现有接触几何仍需单独改进和验证。
5. P4.3 冻结的 20 条 train / 20 条 holdout 规则假设仍采用 600 步静置。按原协议生成它们，主要是在自定心后的状态上抽样，不能代替本诊断，也不能叫作 AI 训练。

## 代码与复现

新增 `--initial-settle-steps N`，允许非负整数，默认 `600`。每条 schema v9 JSON 在 `inputs.initial_settle_steps` 记录实际步数。已有默认行为未变。

复现示例：

```powershell
& .venv\Scripts\python.exe src\diag_feed_chuck.py --v-jaw --lift --no-lock `
  --control-mode M1 --initial-dy-mm 3 --initial-dz-mm 2 `
  --initial-yaw-deg 5 --initial-settle-steps 0 `
  --case-id settle0-dy3-dz2-yaw5-M1 `
  --json-out _build\settle-time-study\settle0-dy3-dz2-yaw5-M1.json
```

## 结论与下一步

这不是夹具搜索，也没有证明适应任意来料。下一步应确认工件是在机械臂移动期间、哪个支撑接触阶段完成自定心，并检查 M1 的抓取目标与实际夹爪位姿是否可达；然后再决定是让工装稳定保留偏移，还是把视觉测量放在更靠近抓取的时刻。先不要生成原计划的 40 条随机样本来宣称泛化。

验收：0/600 步入口和位姿记录通过针对性测试；单测 **40/40**；`verify_all.py` 完整回归 **10/10**。默认 600 步全物理送料保持 PASS；本补充诊断不改变正式 P4.4 的 243 例结果。
