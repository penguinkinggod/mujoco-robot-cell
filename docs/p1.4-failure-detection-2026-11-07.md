# P1.4 故障检测验收

日期：2026-11-07

## 这张卡做了什么

这次不调夹爪、不改运动路线和通过阈值，专门检查系统能不能分清正常送料、夹空、机器人撞机和数值异常。

检查时发现一个真实漏报：机械臂外壳与机床几何的碰撞掩码分别是 `(8, 12)` 和 `(8, 1)`。它们在 MuJoCo 中可以发生接触，但旧检测器只认 `(1, 8)`，所以会漏掉“外壳撞机床”。现在按模型中的机械臂身体层级和机床碰撞掩码识别碰撞几何，不再把 `contype` 的单个数字当作对象身份。

## 验收结果

| 场景 | 检查结果 | 说明 |
|---|---|---|
| 正常全物理送料 | `completed`、PASS，`robot_machine_contact_max=0` | 基准没有被新检测器误判 |
| 来料 `dy=+50 mm`，夹空 | `aborted`，`abort_stage=grasp`，`grasp_contact_count=0`，硬失败 `grasp_empty` | 没进入搬运或卡盘夹紧；可计为一次失败尝试 |
| 注入机械臂外壳-机床外壳碰撞 | 完整送料记录中接触计数大于 0，硬失败包含 `robot_machine_collision` | 碰撞体在受控用例中移入机械臂路径；这是检测器测试，不是正常工况或真实机器人碰撞验证 |
| 运行时注入 NaN | `execution_status=error`，原因 `non_finite_state`，`outcome_class=runtime_error` | 不误报成普通物理失败或成功 |
| 高 IK 残差探针 | 插入 47 mm、站位 −17 mm：feed 残差约 29.20 mm，路径峰值约 70.20 mm；结果报接触不足、拉拔失败和质量失败 | 目前没有经过验证的专用“不可达”判据，因此不贴 `unreachable` 标签；大残差只能作为线索 |

自动测试在 [tests/test_feed_failure_detection.py](../tests/test_feed_failure_detection.py)，覆盖正常初始状态、生成的 8/8 外壳碰撞、完整流程中的碰撞硬失败、夹空 ABORT 和 NaN ERROR。五项均通过。

## 为什么这样处理不可达

“IK 残差大”表示末端离目标远，不单独说明原因一定是机械臂够不到。也可能是载荷下伺服跟踪误差、目标定义、夹持偏移、路径上的某个点或数值问题。47 mm 探针确实失败，但现有程序只可靠报告了接触不足、拉拔失败和姿态/偏心质量失败；没有一个经验证的关节限位/全路径可达性检查。因此本卡不新增随意的残差阈值，也不把它改写成“不可达”。

后续若要做专用可达性判定，应单独验证关节限位、IK 收敛状态和整条轨迹，而不是只看最后一个毫米数。

结果：故障检测单测 **5/5**；完整项目回归 **10/10**。此前 9 项项目检查保持通过，新增第 10 项负责运行这组故障检测测试。

本地 `_build/p14_*.json` 和日志可供本机查看，但 `_build` 被 Git 忽略，不作为跨机器的长期证据；可复现逻辑已提交在测试文件里。

## 结论和边界

- 修复并验证了机器人外壳碰撞的漏报；普通接触不因该规则误判为机器人撞机。
- 正常、夹空、受控碰撞、数值异常四类均有可重复检查。
- 没有宣称已经实现通用不可达分类；P1.4 只记录了高残差失败探针及其证据边界。
- 所有结论只针对当前 MuJoCo 模型，不代表真实机械臂或机床安全认证。
