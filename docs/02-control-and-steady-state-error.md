# 02 · 控制与静差：为什么 PD 停在 75.5° 而不是 90°

## 现象

跑 `demo_01_pendulum.py`，三条曲线：

| 控制方式 | 4 秒后角度 | 和目标 90° 差多少 |
|---|---|---|
| 不给力矩 | 17.1° | 一直在摆，根本不停 |
| 只有 PD | 75.5° | **差 14.5°** |
| PD + 重力前馈 | 90.0° | 差 0.00° |

## 第一层：为什么 PD 会停住，但停不到目标

PD 控制律就两行：

```
误差 = 目标 - 当前
力矩 = 25 × 误差 - 3 × 速度
```

系统最终会停在"误差产生的力矩 = 重力产生的力矩"的那个位置。
摆是 1 kg、杆长 0.5 m，重力矩 = m·g·L·sin(θ)。到 75.5° 时，PD 产出的力矩刚好顶住重力，于是就停在那儿了——**没到目标，也不需要再往上了**。

这叫**静差（steady-state error）**。不是代码写错了，是 PD 本身的性质：它只认误差，不认载荷。

## 第二层：怎么消掉静差

思路：**先算好"托住这个姿势需要多大力矩"，把这一份先给出去，PD 只管修正剩下的误差。**

这就是"前馈"。代码里这一行：

```python
u += float(data.qfrc_bias[0])
```

`data.qfrc_bias` 是 MuJoCo 算好的**偏置力**（重力 + 哥氏力）。你不用自己推公式，
引擎每步都算好了。加上这一项，PD 的误差从 14.5° 变成 0.00°。

这在机器人里叫**逆动力学前馈 + PD 反馈**，是所有工业机械臂控制器的骨架。
不是"高级技巧"，是标准做法。

## 第三层：你该改什么

打开 `demo_01_pendulum.py`，找这两行：

```python
KP, KD = 25.0, 3.0
```

1. `KP = 5`：太软，摆会晃很久才停，甚至停不住。
2. `KP = 200`：太硬，会冲过目标然后来回振荡（超调）。
3. `KD = 0.5`：阻尼不足，来回摆。
4. `KD = 30`：阻尼太大，动作拖沓。

**这就是调参。** 真实机器人调试现场，工程师干的最多的事就是这个。
你现在改一行、跑一次、看一张图，就是在做同一件事。

## 📌 高数在这里用在哪

`sin(θ)` 的线性化、`qfrc_bias` 的推导、稳定性判据（极点位置），
背后都是高数里的导数和微分方程。你现在不用会推，但等你学到"一阶线性微分方程"，
回头看这个摆，会有"哦原来是这个"的感觉。

**先有现象，再有数学** —— 顺序别倒过来，倒过来就是背公式。
