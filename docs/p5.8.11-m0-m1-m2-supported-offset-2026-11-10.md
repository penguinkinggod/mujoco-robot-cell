# P5.8.11：有支撑 `dy=+3 mm` 来料的 M0/M1/M2 对照

完成日期：2026-11-10

## 本轮问题

P5.8.10 已验证：工件和两端 V 托架一起相对机器人、卡盘偏移 `dy=+3 mm` 后，真实重力静置 600 步仍保留该偏差。本轮沿用这个物理来料，只改变机械臂规划时能使用的位姿信息：

- **M0 固定目标：** 仍瞄准 nominal 的工件中心，不读取本次来料偏差。
- **M1 真值重定位：** 使用静置后 MuJoCo 中的真实工件位姿；它是理想 oracle，不是视觉系统。
- **M2 带误差估计：** 使用冻结样本给出的“真值 + 合成误差”，不是相机测量结果。

希望观察的不只是最后有没有 `PASS`，还包括下降/夹紧是否碰推工件，以及抓取瞬间的状态。

三例都完成六个送料检查点；M0/M1/M2 各 `1/1` 按当前项目判据 PASS，没有抓空、ABORT 或运行错误。完整送料的阶段指标和抓取时姿态给出不同排序：M0 的最终同轴与余量偏心数值较小，但抓取时姿态指标明显较大，下降阶段接触和中心移动也最多；M2 的交接峰谷较低，但最终余量偏心最接近 `2.0 mm` 暂定门槛。**目前没有可据此宣布的全面赢家。**

## 怎么解释

最有用的发现是 M0 不是“目标错 3 mm 就一定抓空”。在这一个来料样本里，机器人下降/夹紧时与工件产生较多接触，工件中心从抓取前参考位姿最多移动 `5.302 mm`，轴线最多变化 `6.343°`，随后仍完成送料并满足现行端点判据。`grasp_tilt_deg=23.303°` 是抓取时工件相对 nominal 姿态的完整旋转差，其中可能包括圆柱轴向自转，不能直接读作轴线倾斜 23.303°。M1/M2 的抓取阶段位移较小。换句话说，端点 `PASS` 会遮住过程中的抓取位姿差异；如果项目要比较“抓得稳不稳”，仍需要定义并验证独立的过程门槛，而不能只看最后余量偏心或送料 PASS。

同时，M0 的最终偏心较小并不证明固定目标更好：过程里的接触推动可能改变了棒料状态，`grasp_tilt_deg=23.303°` 也远高于 M1/M2。反过来，M1/M2 本例均 PASS 也不能证明真机视觉可达到同样精度。M2 只是人为设定的估计误差输入。

## 证据边界

- 每种模式只有一个单例；`1/1 PASS` 是本条件下的结果，不是成功率、重复性、置信区间或任意姿态鲁棒性。
- 只测 `dy=+3 mm`，没有证明 `dy=-3 mm` 或其他高度、偏航、尺寸也类似。
- M1 读取 MuJoCo 真值，不代表相机、标定或定位模型。
- M2 的误差来自冻结的合成样本，不是传感器精度依据。
- `FEED_METRIC PASS` 只表示通过当前项目判据；其中余量限值 `2.0 mm` 尚未得到加工图纸/工艺确认。
- 接触/穿透结果来自未做实物标定的 MuJoCo 接触模型；抓取阶段位移和 `grasp_tilt_deg` 当前是诊断值，没有独立合格门槛。
- 本轮没有修改路径、夹爪、机械臂参数、接触模型、阈值或代码默认值。

## 原始结果与复现

JSON 与终端日志存放在 Git 忽略目录 `_build/p5.8.11-m0-m1-m2/`：

- `p5811_m0_supported_dy_plus3.json` / `.log`
- `p5811_m1_supported_dy_plus3.json` / `.log`
- `p5811_m2_supported_dy_plus3.json` / `.log`

三种模式统一使用同一条冻结 M2 误差作为命令输入；M0/M1 按定义忽略 M2 误差，M2 使用它。以下 PowerShell 命令可复现三例：

```powershell
$common = @(
  '-X', 'utf8', 'src\diag_feed_chuck.py',
  '--v-jaw', '--lift', '--no-lock',
  '--initial-dy-mm', '3', '--support-follows-initial-pose',
  '--initial-settle-steps', '600', '--random-seed', '0',
  '--m2-error-dy-mm', '0.203443',
  '--m2-error-dz-mm', '0.312274',
  '--m2-error-yaw-deg', '1.051870'
)
foreach ($mode in @('M0', 'M1', 'M2')) {
  $modeLower = $mode.ToLowerInvariant()
  & .\.venv\Scripts\python.exe @common `
    --control-mode $mode `
    --case-id "p5811_${modeLower}_supported_dy_plus3" `
    --json-out "_build\p5.8.11-m0-m1-m2\p5811_${modeLower}_supported_dy_plus3.json" `
    2>&1 | Tee-Object -FilePath "_build\p5.8.11-m0-m1-m2\p5811_${modeLower}_supported_dy_plus3.log"
  if ($LASTEXITCODE -ne 0) { throw "$mode failed with exit code $LASTEXITCODE" }
}
```
