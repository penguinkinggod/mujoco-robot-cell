# P2.4 插入深度扫描器错误处理

验收日期：2026-11-08

> 历史验收快照。本文的“下一步 P4.1”已完成；当前机械主线以仓库根目录 [CURRENT.md](../CURRENT.md) 为准。

## 目标与边界

保证插入深度扫描器只把完整、匹配当前实验 case 的 schema v6 结果映射为 PASS/FAIL/ABORT。缺文件、损坏或不兼容 JSON、子进程启动失败、超时和退出码冲突都记为 ERROR，不能误报 PASS。

本卡只改扫描器、错误处理单测与验收文档；未改送料动作、控制、夹具、仿真参数或成功判据。P2.3 的 JSON schema v6 保持不变。

## 实现内容

- 子进程设置 600 秒超时；启动异常、超时、缺失/损坏 JSON 均在 CSV 写出 `status=ERROR` 和具体原因。
- 每次运行前删除目标 JSON；即使目录里有上一轮有效 PASS，本轮未产出文件也会报错，不会复用旧结果。
- 只接受整数 `schema_version=6`、匹配的 `case_id`、合法执行状态及必要字段。completed 结果还需具备扫描器所用指标、有限数值和 feed IK 残差；`overall_pass` 必须与 hard/quality 判据一致。
- 对照子进程退出码：completed PASS 必须退出 0，completed FAIL 或 ABORT 必须退出 1。不相符时记 ERROR；正常的仿真 FAIL/ABORT 仍各自保留，不混成程序错误。
- CSV 保留 `case_id`、输入、退出码、schema 版本、JSON 路径和错误原因，便于从汇总行定位逐 case 文件。
- `verify_all.py` 的语法覆盖加入扫描器及其单测。

## 验收证据

- 独立扫描器单测覆盖 PASS、FAIL、ABORT、缺失结果、上一轮残留 JSON、损坏 JSON、旧/非整数 schema、v6 缺字段、子进程启动失败、超时、仿真 runtime error，以及非预期退出码不能覆盖 PASS JSON。扫描器单测 **10 项通过**。
- 全部单测 **20 项通过**。
- 真实完整送料扫描：7.75 mm FAIL（余量偏心 2.19 mm）、8 mm FAIL（2.28 mm）、10 mm PASS（0.92 mm）、25 mm PASS（0.70 mm）。最浅 PASS 仍为当前固定初态的 10 mm，不是通用标准。CSV 与逐 case JSON 位于 Git 忽略的 `_build` 目录。
- 完整 `verify_all.py` **10/10 通过**；`py_compile` 与 `git diff --check` 通过。
