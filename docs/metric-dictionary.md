# 机械臂送料指标字典

更新：2026-11-10

## 用途与版本

本文是圆柱棒料送料任务的 v1 测量约定，不是行业标准。当前阈值用于项目内对照，后续可依据实验、工艺假设或可靠工程依据调整。

每条实验结果应区分两个版本：

- `metric_schema_version`：指标怎么算、单位是什么、在哪个阶段测。
- `criterion_set_id`：这次实验用哪一组 PASS/FAIL 门槛。

因此，改阈值不应改变指标公式，也不应覆盖历史结果。每次修改判据时，新增判据版本并记录修改原因；旧 case 保留原始测量值和原判定。若要按新门槛重新评估旧 case，应另存重评结果，并标明新 `criterion_set_id`。

目前可将本表门槛称为 `feed-criteria-v1`。下列门槛大多是**项目约定**；它们既不是生产安全保证，也不代表真实车床或机器人厂商的验收标准。

## 适用场景

主实验是 Ø20 × 80 mm 棒料、完整机械臂送料、V 槽抓取、无运动学搬运锁。卡盘单站测试、历史运动学锁路径、官方兼容场景应单独标注，不能混成一个通过率。

`verify_all.py` 的通过数只表示该代码版本中列出的回归检查通过，不代表全部检查都是同一种真实物理送料模式，也不代表指标已由实机验证。

## 指标表

### 任务有效性与过程异常

这些指标回答“任务是否按预期完成”。硬失败不可由其他误差较小或平均值较好抵消。

| ID | 指标 | 定义 / 单位 | 测量阶段 | v1 判据 | 判据依据与状态 |
|---|---|---|---|---|---|
| V-01 | V 槽抓取接触数 | 棒料与 V 爪几何的接触记录数，个；不是独立接触面数量 | 抓取闭合完成、搬运开始前 | 全物理 V 槽路径必须 ≥ 1 | 当前代码硬失败；零接触时中止，不继续搬运或闭卡盘。这是任务有效性检查，不证明抓持可靠 |
| V-02 | 卡盘接触数 | 棒料与三爪 `jaw_geom` 的 MuJoCo 接触记录数，个 | 卡盘闭合并稳定后 | ≥ 6 | 项目约定；接触记录数不等于三爪均匀受力的证明 |
| V-03 | 20 N 轴向拉拔位移 | 沿世界 x 施加 `-20 N` 后，棒料 x 位移绝对值，mm | 机器人退出、卡盘保持后 | ≤ 2.0 mm | 当前代码硬失败条件，阈值为项目约定；默认仿真 700 步（0.002 s/步，即 1.4 s），仅覆盖该方向、大小和时长 |
| V-04 | 棒料外加力峰值 | 交接期间施加到棒料自由关节平移自由度的最大外力分量，N | 抓取完成至交接结束 | 真实 V 槽交接路径要求为 0 N | 实验约束：不允许用外力替机械臂对中；重力、接触力、夹爪力不是此项外加力 |
| V-05 | 机器人-机床接触 | 按机器人碰撞体与机床碰撞类别识别到的接触记录 | `track_pen` 采样的任务阶段 | 当前代码中最大记录数必须为 0 | 当前实现是硬失败条件；由于分类依赖模型几何身份/碰撞类别映射，仍需验证是否有漏报或误报，不应称为已完整验证的碰撞安全保证 |

### 姿态与装夹质量

这些指标回答“装夹结果是否达到本项目当前几何要求”。数值可以在新判据版本中调整。

| ID | 指标 | 定义 / 单位 | 测量阶段 | v1 判据 | 判据依据与状态 |
|---|---|---|---|---|---|
| Q-01 | 同轴误差 | 棒料中心相对卡盘轴线的径向距离：`sqrt(dy² + dz²)`，mm | 机器人退出、结果稳定后 | ≤ 2.0 mm | 项目约定；只看中心位置，不包含倾斜造成的端部偏心 |
| Q-02 | 轴线倾角 | 棒料轴线与世界 x（本模型的卡盘轴线）的夹角，度 | 机器人退出、结果稳定后 | ≤ 10° | 项目约定；不是棒料完整姿态误差，圆柱绕自身轴滚转不计入 |
| Q-03 | 交接 z 峰谷位移 | 从卡盘开始夹紧到松爪和退出期间，棒料中心 z 的最大值减最小值，mm | 整个交接过程 | ≤ 12 mm | 宽松甩料护栏，不是精度目标；当前代码注释称这是项目护栏 |
| Q-04 | 棒料余量偏心 | 棒料两端到卡盘轴线的径向距离中较大的一个，mm | 机器人退出、结果稳定后 | ≤ 2.0 mm | 基于当前 Ø20 粗车至 Ø16 的单边 2 mm 余量假设；工件/加工目标改变时必须重定 |
| Q-05 | 重力静置位移 | 棒料中心 z 的绝对变化，mm | 释放临时支撑后先静置 1600 步、再等待 800 步，取随后 800 步窗口的 z 起终点差 | ≤ 2.0 mm | 项目约定；0.002 s/步时测量窗口为 1.6 s，只检查 z 方向；必须注明实际场景和外力状态 |

### 其它硬条件

以下条件同样参与当前 `overall_pass`，但不是上表的质量指标：

| 条件 | 当前代码规则 | 来源与限制 |
|---|---|---|
| IK 结果存在 | 缺少 IK 结果为硬失败；不以固定残差上限直接判不可达 | 任务有效性规则；残差需结合实际轨迹、关节限制解释 |
| V 爪抓取成功 | 全物理 V 爪路径至少 1 条棒料接触记录；零接触会提前中止 | 不代表可靠性或抓持力达标 |
| 棒料外加力 | 调整后的送料路径中自由关节平移外力峰值须 ≤ `1e-6 N` | 这是禁止用外力替机器人对中的实验约束；`1e-6 N` 是近零数值容差，仅对相应 `tuned` 路径执行，不是工程载荷公差 |
| 已识别的机器人-机床接触 | 最大记录数须为 0 | 代码按当前几何分类硬失败；类别映射尚需覆盖验证 |

`criterion_set_id=feed-criteria-v1` 中最初的同轴 `2 mm`、倾角 `10°`、接触数 `6`、静置位移 `2 mm` 和拉拔位移 `2 mm` 可追溯到 2026-11-05 的送料原型记录，但没有外部规格引用。交接 `12 mm` 护栏和余量偏心 `2 mm` 在 2026-11-07 的代码历史中加入/调整；余量值按 Ø20 毛坯车到 Ø16 的示例假设计算。具体审计、代码行为和历史依据见 [P5.8.9 判据审计](p5.8.9-feed-criteria-audit-2026-11-10.md)。

## 汇总判定规则

先分清三个问题，不要用一个“有效/无效”全包：

1. `trial_data_valid`：这次仿真是否留下可解释的尝试记录。正常完成或按预期抓空后中止，都算可用试验记录；NaN 等运行错误不算有效尝试结果。抓空没有后续卡盘质量指标，相关指标应为空，不能补零。
2. `evaluation_scope`：这条记录属于主全物理送料、带运动学锁的历史参考，还是其他诊断配置。只有声明的主实验配置进入主实验统计；其他配置可以报告，但不混入同一个成功率。
3. `outcome_class` 与原判据：可用的主实验尝试再分成功、硬失败、质量失败或中止。`hard_pass`、`quality_pass`、`overall_pass` 仍保留原含义，不能因新增标签而重算或覆盖。

P1.3 的机读字段写在 case JSON 顶层，`schema_version=3`；P2.1 加入复现配置字段升为 v4；P2.2 增加标准阶段检查点升为 v5；P2.3 增加全过程接触与外加载荷汇总升为 v6；P4.2 增加扰动前/后位姿、world-Z yaw 和抓取目标快照升为 v7；P4.4 增加规划模式、目标来源和携带偏移审计升为 v8；P4.4 补充诊断增加初始静置步数字段升为 v9；P5.2 加入送料模型 reset 位姿来源和动作前连续稳定窗口升为 v10；P5.3 接触重叠时空信息及几何参数升为 v11，分阶段工件位移诊断升为 v12；P5.6 增加可选的逐物理步相对位姿/接触时间序列升为 v13；P5.8.10 记录支撑坐标系随来料位姿变换的输入模式升为 v14；P5.8.13 增加可选的抓取接近计划/实际关节和末端轨迹记录升为 v15；P5.8.14 增加卡盘夹紧交接接触/工件运动记录升为 v16；P5.8.15 增加可选三爪接触触发松爪控制和最终脱离状态升为 v17；P5.8.16 增加卡盘闭合前保持/松爪观察、导套/托架接触拆分和窗口末步摘要升为 v18。字段扩展不改变指标算法或送料判据版本：

- `schema_version=18`：当前结果结构版本；包含 v17 字段，进一步把固定件接触拆为导套和下半环托架统计，并支持卡盘仍张开时对照机器人夹爪保持/原地松爪。最后一步记录夹爪控制值、V 爪及固定件接触点/法向力摘要；接触力未标定，观察模式不运行普通送料判据。相关分析器兼容读取 v14-v18。
- `schema_version=17`：历史版本；包含 v16 字段，并在卡盘交接诊断中记录机器人松爪模式、三只卡盘爪同时接触时刻、松爪斜坡完成时刻和最终连续无 V 爪接触窗口；`FEED_RELEASE_AFTER_TRIPLE_CONTACT=1` 会改变松爪时序，必须同时开启 `FEED_TRACE_CLAMP_HANDOVER=1`。若松爪后接触再次出现，脱离确认会被清除。该功能是显式诊断，不改默认流程和送料判据。
- `schema_version=16`：历史版本；包含 v15 所有字段，并可由 `FEED_TRACE_CLAMP_HANDOVER=1` 选择性记录卡盘夹紧交接逐物理步历史，包括三只卡盘爪的接触点/法向力、机器人 V 爪和固定件接触、棒料中心/轴线、机器人夹爪命令、工具位姿与棒料相对工具位姿。默认不保存该时间序列；接触力未按实机标定，诊断不改变 PASS/FAIL。
- `schema_version=15`：历史结构版本；包含 v14 所有字段，并可由 `FEED_TRACE_PICKUP_MOTION=1` 选择性记录“接近/侧向进入”的计划关节位置与速度、关节控制输入与实测状态、计划/实际末端位姿及跟踪误差。默认不保存逐步轨迹；该诊断不改变 PASS/FAIL。
- `schema_version=14`：历史 JSON 字段结构版本；包含 v13 的逐步追踪开关，并在 `inputs.requested_initial_pose` 记录 `support_frame_mode`，启用支撑随动时记录 `transformed_support_geom_count`。旧的 schema v13/v14 结果保留原结构，不能伪装成新版本。
- `schema_version=13`：包含 v12 字段，以及由 `FEED_TRACE_RELATIVE_MOTION=1` 显式启用的抓取后搬运/进给逐物理步记录。时间序列含工件和夹爪世界位姿、夹爪坐标系相对位移/轴线变化、相邻步变化、棒料接触对的法向力与接触距离。默认不保存逐步历史；所有新量只作诊断，不改变 PASS/FAIL。历史 v8、v11、v12 记录保留原结构，不能伪装成 v13。
- `metric_schema_version=1`：指标定义版本。
- `criterion_set_id=feed-criteria-v1`：PASS/FAIL 门槛版本。

P2.1 还记录工件输入、初始位姿、控制模式、实际参数、已设置的相关环境变量、仿真选项、代码与依赖版本；P2.2 记录六个稳定节点；P2.3 记录逐物理步采样后的接触/外加载荷汇总和节点瞬时快照；P4.2 增加名义位姿、施加扰动后的静置前位姿、静置后的抓取前真值、工件轴线单位向量和抓取目标来源；P4.4 补充诊断记录 `inputs.initial_settle_steps`；P5.2 在 `inputs.workpiece` 记录 reset 模型的实际 nominal 起点及来源，并记录最后 100 个静置步的运动、接触和外加力；P5.3 按动作阶段和几何对记录负接触距离、持续步数、最深接触位置及碰撞几何参数，并在 v12 记录接近推料与抓取后相对夹爪运动；P5.6 可在 v13 逐物理步记录相对位姿及每个工件接触对的距离/法向力；P5.8.10 在 v14 记录初始来料支撑坐标系是否随请求位姿刚体变换；P5.8.13 在 v15 可选记录抓取前计划/实际关节与末端运动；P5.8.14 在 v16 可选记录卡盘夹紧/稳定/松爪/退出中的工件位姿、三爪与机器人/固定件接触时序；P5.8.15 在 v17 记录可选三爪接触后松爪控制与最终脱离状态；P5.8.16 在 v18 记录卡盘闭合前的保持/松爪观察及导套/托架接触拆分。20 N 拉拔测试在 `pull_test` scope 单独统计，不算送料期间的隐藏外力。详细验收见 [P2.1 实验 JSON 规范](p2.1-case-json-schema-2026-11-07.md)、[P2.2 六节点记录](p2.2-checkpoint-records-2026-11-08.md)、[P2.3 接触与外力记录](p2.3-contact-force-records-2026-11-08.md)、[P4.2 扰动位姿记录](p4.2-zero-and-axis-perturbations-2026-11-08.md)、[P5.2 稳定性验收](p5.2-pre-motion-stability-2026-11-09.md) 和 [P5.3 阶段验收](p5.3-phase-acceptance-2026-11-09.md)。

| 字段 | 解释 |
|---|---|
| `evaluation_scope` | `primary_physics_feed`、`kinematic_lock_reference` 或 `diagnostic_configuration` |
| `trial_data_valid` | 完成或受控中止的仿真记录为 true；数值运行错误为 false |
| `include_in_primary_trial_stats` | 是否进入主物理送料统计；可用的 ABORT 也计入尝试次数和失败数 |
| `physical_task_success` | 只有主实验配置完整完成且原 `overall_pass` 为 true 才为 true |
| `outcome_class` | `physical_success`、`hard_fail`、`quality_fail`、`aborted`、`runtime_error`、`reference_pass/fail`、`diagnostic_pass/fail` 或 `missing_result` |

运行错误与子进程无 JSON 结果均单独报告，不算物理成功，也不静默当成物理失败。带锁对照即使 `overall_pass=true`，也只能标为 `reference_pass`，不得计入主实验成功率。

正式报告至少包含各指标原始值、`metric_schema_version`、`criterion_set_id`、控制模式、工件与夹具参数、代码版本、评价范围、数据有效性和结果类别。总体 PASS 不得隐藏失败阶段；批量统计报告成功分子/分母、失败类别、运行错误数量、分布和最差 case，不要只给平均值。

## 修改判据的记录模板

新增判据版本时记录：

| 字段 | 示例内容 |
|---|---|
| 新 `criterion_set_id` | `feed-criteria-v2` |
| 修改项 | `Q-01` 同轴误差上限 |
| 旧值 → 新值 | `2.0 mm → 待定` |
| 修改原因 | 工艺目标、敏感性实验或外部工程依据 |
| 影响范围 | 哪种尺寸、路径、工装和实验集适用 |
| 重评方式 | 是否重算历史 case；保留原始判定，不覆盖 |
| 批准状态 | 草案 / 项目采纳 / 有外部依据 |

没有数据或外部依据时，可以暂时调整以开展探索，但必须标为“草案”，不能宣称新阈值已经成为通用工程标准。
