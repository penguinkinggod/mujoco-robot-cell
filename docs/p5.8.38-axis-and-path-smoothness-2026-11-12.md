## 三、排除的四个假问题（重要，避免以后重追）

### 3.1 jerk 峰 7.9e6 是 2 ms 差分噪声

`dt=0.002 s`，jerk = 位置三阶差分，放大 1.25e8 倍。

| 判据 | 数据 |
|---|---|
| jerk > 1e6 的帧 | 155 / 11756（**1.3%**） |
| 尖峰成簇长度 | 2–8 帧（**4–16 ms**），伺服带宽跟不上 |
| **50 ms 低通后 jerk 峰** | 8.23e6 → **5.45e5**（**降 15 倍**） |
| TCP 相对 50 ms 滑动中位的偏离 | 中位 **0**，p99 **0.025 mm**，峰 0.617 mm |

**轨迹本身是光滑的。** 我一度去调 `SO101_KP/KV`（70→150→300，kv 2.6→5→8），
结果 KP 越高 jerk 越大（70→1.06e7，300→2.45e7），`tilt` 从 1.32 恶化到 1.31/0.72。
**方向完全错了，已全部回滚。**

### 3.2 “38 段停顿”全是收敛尾段

旧判据「速率 <1 mm/s 且 ≥5 帧」。改用「净位移 + 跨度」分类：

| 类别 | 段数 | 合计 |
|---|---:|---:|
| 收敛尾段（净位移 <0.5 mm 且跨度 <0.5 mm） | **22** | 8.102 s |
| **真停顿** | **0** | 0.000 s |

最长那段 `t=[10.160, 10.994]` 0.834 s，净位移只有 0.2019 mm，三轴跨度
0.045/0.178/0.084 mm——是 `ec600` 闭环到位后的微调，**不是停顿**。

### 3.3 “9 次方向反转”是低速方向噪声

`u = v/|v|`，当 |v| 只有 0.5–5 mm/s，数值误差就能让 cos 跳到 −1。
逐帧核对 `t=11.500`（cos=−1.000）：`vx` 全程为负 −4.5→−0.5，
TCP x 单调 209.649→209.549，**根本没有折返**。

### 3.4 拐角加密无效甚至更差

`PATH_CORNER_DENSIFY` 默认 0（从未启用）。开启后：

| case | 搬运绕行比 | coax |
|---|---:|---:|
| base | **1.98** | 0.0871 |
| densify (K=3) | 2.03 | 0.5425 |
| dens_k5 | 2.03 | 0.0862 |
| dens_k8_w08 | 2.02 | 0.5184 |

`FEED_CARRY_END_HOLD` 数值**完全相同**（没生效）。
绕行比 1.98 本身不是浪费——搬运段是「对中→抬起→横移→下降」的折线，
路点折线长 382 mm，实际 486 mm，比值 1.27，属于末端过冲（已由第二节修掉）。

## 四、回滚：进给不切 4 段（试过，不划算）

`move3` 每轮 `kw = {"s0": k/iters, "s1": (k+1)/iters}`，而 `move()` 里
`s = (_smooth(t) - S0) / span` 把 `[s0,s1]` 重映射到 `[0,1]` ——
**每轮都是独立 rest-to-rest 起停**。进给 4 轮 = 4 次起停，TCP x 走 V 形：

```
进给#1  起点 206.548 → 最低 204.455（回退 2.093 mm）→ 终点 211.258
进给#2  回退 1.703 mm
```

试过改成每轮走完整 quintic：回退只从 **2.093 → 1.946 mm**，而 `coax`
从 **0.0804 崩到 0.5296**。**已回滚。**

回退量与 `FEED_PATH_END_CLOSE` 无关（120/300/600 全是 2.093），
确认是分段起停而非两套闭环解不一致。

## 五、附带改动：move_path 前馈速度改解析导数

旧：`qd = (pchip(s2) - pchip(s)) / dt`（前后两帧差分）
新：`qd = dpchip(s) * sd`（PCHIP 解析导数）

拐角加密区采样点密集，s 两帧间变化不均匀，差分会跳变。这个改动本身更正确，
但它**不是** jerk 峰的主因（改完 jerk 峰 8.05e6，几乎没动）。保留。

**副作用**：这个改动让质量失败 fixture 的 `stock_ecc` 从 2.1880 掉到 1.9500，
刚好卡在 2.0 阈值下方。见第六节。
