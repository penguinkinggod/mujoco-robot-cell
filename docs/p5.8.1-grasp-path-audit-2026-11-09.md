# P5.8.1 首轮抓取路径审计

日期：2026-11-09

## 本轮范围

只读检查 SO-101 主送料路径和现有独立抓取保持检查，并按当前主线命令复跑一次 nominal。没有修改机械臂轨迹、夹爪几何、接触参数或 PASS/FAIL 判据。

## 主流程 nominal 复跑

命令：

```powershell
.\.venv\Scripts\python.exe -X utf8 src\diag_feed_chuck.py --v-jaw --lift --no-lock --json-out _build\p5.8-nominal\baseline.json
```

JSON 结果保存在被 Git 忽略的 `_build/p5.8-nominal/baseline.json`。当前名义工况复现完整物理送料 `PASS`：

| 指标 | 结果 | 应如何理解 |
|---|---:|---|
| 最终同轴误差 | `0.547 mm` | 本项目现有判据下通过 |
| 最终轴线倾角 | `1.464°` | 相对卡盘轴线，不包含圆柱绕自身轴滚转 |
| 卡盘接触记录 | `30` | 接触点记录数，不是三只爪的数量 |
| 交接 z 峰谷 | `2.948 mm` | 小于当前 `12 mm` 项目护栏 |
| 最终余量偏心 | `1.420 mm` | 小于当前 `2.0 mm` 项目假设 |
| 夹紧时 V 爪—棒料接触记录 | `2` | 真实接触记录数；不等于已证明抗扰稳定 |
| 搬运/进给最大相对夹爪平移 | `8.152 mm` | 在 `7.912 s` 达峰，目前只是诊断量，没有独立合格阈值 |
| 搬运/进给最大相对轴线变化 | `1.528°` | 相对夹爪坐标中的轴线变化 |
| 最大 V 爪接触重叠 | `2.991 mm` | 出现在搬运阶段的 `shaft_geom|moving_jaw_pad_v2`，接触模型未标定 |

这说明“最终卡盘装夹通过”与“机械臂搬运期间稳定抓持”是两项不同的结论。当前不能仅凭端到端 `PASS` 宣称抓持已经调好；也不能仅凭 `8.152 mm` 宣称实际夹持一定有害。

## 现有独立抓取检查的适用范围

运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 src\check_grip_hold.py --v --mu 0.05
```

此检查报告 0 个夹爪—棒料接触、5 N 下拉后位移 `351.3 mm`、抬起时工件未跟随。**这组结果不能当成主送料抓取的失败结论**，因为它没有复用主流程的完整初态与接近路径：主送料流程先静置工件，再通过测得的 V 槽开口方向侧向进入，之后下降、闭爪并等待夹爪斜坡完成；独立检查则直接用 `Arm.move_to` 从上方接近并下降。接触位置和来料初态不一致，二者不是公平对照。

因此本轮不根据该检查修改 V 槽、闭爪量或摩擦参数。后续抓稳测试应复用主流程的来料静置、侧向进入、下降、闭爪和完成闭爪等待；再在不使用运动学锁、不让托架替夹爪承重的条件下，单独测试真实重力保持与抬升跟随。

## 代码阅读中的判读提醒

- 当前主线命令包含 `--no-lock`，运行日志明确显示“物理接触无锁”。`diag_feed_chuck.py` 文件开头仍有旧文字称搬运是运动学锁，和当前实际主线模式不一致；阅读时应以命令、结果 JSON 的 `carry=physics` 及实际控制分支为准。此项是文档/注释过期，不是本轮改了行为。
- 中途日志中的 `tilt_deg()` 是完整四元数角差，会把圆柱绕自身轴的滚转也算进去。判读棒料是否偏斜应看轴线角 `axdev()` 或最终 `metrics.tilt_deg`，不要把中途的四元数角差当成轴线倾角。

## 结论与下一步

当前物理送料主流程在名义工况可重复通过，但独立抓稳证据尚未与主流程的真实抓取路径对齐。下一张小任务是制作/修正一个**与主流程同初态、同侧向接近、同闭爪过程**的独立保持检查；先验证该测试确实复现主流程的抓取接触，再测抬升和扰动保持。完成前不改主线默认参数，也不开始夹爪或速度优化。
