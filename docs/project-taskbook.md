# 项目任务总账：方向、交付与接手顺序

更新：2026-11-07。本文是未来工作的统一入口，不是已经实现的功能列表。

## 1. 分工先固定

- 用户：选择目标和范围，理解实验结论，决定是否接受阶段结果。
- 当前 coding agent：按任务卡实现、验证并维护现场文档；一次只推进一张卡，不擅自扩展范围。
- 用户与实现者共同检查判据和实验结论；代码实现不需要另起模型交接。
- 每张卡验收后可做本地 commit；未经用户明确同意，不 push 到 GitHub。失败可以作为实验结果交付，未验证不能写成完成。

## 2. 我们最终要做什么

建议项目名：**面向变尺寸棒料的机器人上下料与夹具配置优化仿真平台**。

核心问题：在指定的棒料尺寸、来料误差和设备范围内，固定 V 槽与固定动作会在哪里失效？能否通过有限夹具候选、抓取站位和送料参数选择，提高成功率，并说明误差与节拍的取舍？

最终用户流程：输入或选择工件条件 → 检查是否在支持范围内 → 选取已验证夹具与动作参数 → 完整仿真送料 → 显示成功或明确失败原因 → 保存结果。超出范围时拒绝给出“保证可行”的方案。

系统输出不是一句“最优”，而是：候选配置、适用范围、失败风险、对照指标、对应实验编号。

## 3. “标准”和“最好”怎么定义

- 分清机械臂夹持长度、夹持站位、卡盘插入深度与加工悬伸。不能用一个“80 mm 夹多少”混指四个量。
- 本阶段是上下料仿真，不包含真实切削安全验证。既有 20 N 拉拔试验只覆盖该载荷方向和工况。
- 保留现有质量阈值作为 v1 项目判据，逐条记录单位、测量阶段、来源和用途；未找到工程依据的值注明“项目约定”，不包装成行业标准。
- 碰撞、夹空、掉料、不可达、数值异常属于任务有效性问题，不能用更低的平均误差抵消。
- 先满足有效性和质量要求，再比较通过率、误差分布、最差样本和节拍。存在取舍时保留多个候选，不捏造唯一的最优分数。
- 最浅通过深度是边界测量，不自动成为默认深度。8 mm 的旧结果只是固定初态离散测试结论。
- “最优”只在已声明的变量范围、候选集合和测试分布中成立；有限试验不能证明覆盖无限种情况。
- V 槽和现有托架保留作对照，不预先认定最好或错误；是否保留由同样样本上的结果决定。

## 6. 每天怎么推进，避免又不知道做什么

每天只回答一个问题、领取一张小任务卡，不以代码行数或 commit 数当进度。

1. 开始：读 CURRENT 和本总账，确认一个卡号、预期产物、禁止改动范围。
2. 学习：写下今天要理解的一个概念，例如坐标系、接触、IK 残差与跟踪误差的区别。
3. 实现：由实现模型完成该卡，遇到基准失败停止扩展。
4. 验收：用户能指出输入、输出、判据，并解释至少一个失败案例。
5. 记录：把卡号、证据路径、结论、未解决问题和下一张卡写回 CURRENT；验收后可本地 commit，推送需等公开成果成熟并经用户确认。

单次交付必须包含：修改文件、为什么改、复现命令、结果文件、通过/失败/未测、适用边界、下一张卡。失败也能形成有价值的学习记录。
