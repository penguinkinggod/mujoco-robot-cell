# 交接：机械臂送料轨迹第一版（2026-11-11）

这份说明可以直接粘贴给新的执行代理。当前任务是把送料轨迹改成一条连续路径，用下面四个数验收；它属于论文和大创主线的“基线调稳 + 可复现评测”，不是一次孤立的调参。不要用最终同轴误差或倾角指标代替轨迹质量判断。

## 项目大方向与本阶段位置

用户是大一学生，目标是形成可复现的大创成果，并在此基础上争取论文。最终系统设想是“来料 → 机械臂抓取 → 送入卡盘 → 分拣”，后续还可能加入 AI；但近期核心成果必须收在“机床接触式装夹问题 + 可复现评测方法”，不能把远期流水线或 AI 当作已经完成的成果。

当前论文主线是：以 SO-101 抓取圆柱棒料并交接给三爪卡盘为具体任务，在固定物理场景、固定样本和分层判据下，先建立可靠基线，再做一个有消融/公平对照的改进，最后在未参与调参的留出集验证。大创的完整成果至少需要：重力条件明确、指标与失败记录可复核、适用边界清楚、改进有对照、结果可复跑。真机迁移和多品种流水线是后续可选分支，当前仿真结果不能写成真机结论。

这次轨迹工作处在“可靠基线”阶段，最低可发表交付不是“某次 `PASS`”，而是：

- **明确的方法**：如何把多个必要动作组成一条连续路径，停点和交接边界如何定义，怎样避免路点处重新规划和 settle；
- **可计算的过程指标**：停点、低速/静止区间、末端速度方向突变、最短运动片段、时间、跟踪误差，并保留接触与最终装夹指标；
- **公平基线**：同一场景、同一样本、同一物理参数下，与当前分段闭环基线配对比较；不能删掉失败样本或只报改善项；
- **消融证据**：至少区分连续路径本身、取消中途 settle、取消/合并末端纠正各带来什么变化；
- **复现材料**：源码、配置、随机种子/初态、结果 JSON、绘图或统计脚本和失败案例；
- **诚实边界**：说明这是指定 MuJoCo 模型、V 槽和三爪卡盘参数下的结果，尚无真机校准；不得把四指标写成工业节拍或总体成功率。

因此新的执行代理应在完成四条轨迹改造后，保存改动前后的配对数据，记录哪些局部参数调整没有效果，并把结果整理成可进入论文实验表的证据。若发现仅靠改增益或加时间才能过四项，应停止调参，重新定义路径目标和执行结构。完整研究边界见 `docs/paper-roadmap.md`，任务分层见 `docs/project-taskbook.md`。

## 用户最新观察

用户肉眼看同一轮送料，仍有四类问题：

1. 机械臂从上方朝料接近时缓慢、一顿一顿；
2. 放到三爪时仍会“点头”；
3. 交接后被夹爪沿棒料轴线直线退出，用户不确定这段是否安全；
4. 离开棒料后侧向撤离仍一顿一顿。

这些是运动连续性质量问题。最终 `coax_mm`、`tilt_deg`、`contacts` 看起来合格，也不能判这四条为通过。

## 本轮唯一验收标准

只按下面四条改，其他动作和判据不动。

1. **停点只允许三个**：抓取点、夹紧点、交接点。除此之外，全程末端速度必须大于 `0.02 m/s`，不能归零或接近零。
2. **不许突然改向**：相邻两帧的末端速度方向夹角不得反向。任何一处超标，本轮就不合格，无论误差指标多好。
3. **抓取段和交接段删除多余动作**：回零、抬升、二次对位、为凑误差的反复微调都算多余。每个保留的路点必须能写成“第几个路点 / 为什么必须 / 去掉会怎样”；说不出理由的直接删除。
4. **整条路径一次规划完再执行**，从起点连续跑到终点，只在抓取、夹紧处停；不允许每个路点重新规划、分段执行。需要判断一次规划是否确实更好。

## 现有实现中已定位的冲突点

- `src/diag_feed_chuck.py:3908` 的 `move_pickup_continuous()` 已有“接近→槽口→下降”单条连续曲线，但抓取前还有一次独立的 `move3()` 末端纠正，会形成新的起停。
- `src/diag_feed_chuck.py:3760` 的 `move3()` 最多把一段拆成 `3–4` 个闭环轮次；每轮在 `move()` 末尾执行 `60–90` 步 settle。用户看到接近和退出时的顿挫，代码上确实存在反复起停结构。
- `src/diag_feed_chuck.py:4136` 的连续抓取结束时固定再执行 `90` 步 keep-alive 静置，使抓取前成为独立停点。
- `src/diag_feed_chuck.py:4922` 的搬运先走 `move_path()`（一条连续轨迹），但随后又单独调用 `move3()` 做“进给”闭环。进给因此重新起步，并在内部最多分三轮。
- `src/diag_feed_chuck.py:5691` 交接后的退出被拆成“沿棒料轴线退 `70 mm`”和“侧向撤离”两段，各自调用 `move3()` / `move()`，中间还有 settle。轴向退出本身是为了避免张开的 V 爪横刮棒料，不能在没有接触证据时直接删掉；应把它并入一条连续撤离路径，并记录 V 爪是否已完全脱离。
- `src/diag_feed_chuck.py:5908` 附近的阶段统计用 `8 mm/s` 判断“静止”，与用户要求的 `> 0.02 m/s` 不是同一门槛。需要为本轮新增四指标统计，不能沿用旧 `phase_stats` 的结论。
- 当前一次完整送料约 `9.77 s`；`_build/p5.8.22-startup-ik/nominal_final.json` 的 `phase_stats` 显示退出相关 `#1/#2/#3` 阶段有大量采样步落在静止区。旧阶段统计只能作为线索，最终必须按 `0.02 m/s` 重新计算。

## 本轮建议的改动方向

先修改执行结构，再做小范围参数调整：

1. 构造一条覆盖“初始位姿→抓取点”的连续轨迹，只在抓取点停；把抓取前的末端纠正并入同一条轨迹的目标和采样，不再追加独立 `move3()`。
2. 构造一条覆盖“抓取→搬运→进给→交接点”的连续轨迹，只在夹紧和交接处停；把进给的闭环补偿改成对整条路径目标的规划修正，不能在末端额外起停一轮。
3. 构造一条覆盖“交接后轴向脱离→侧向撤离”的连续轨迹；先验证轴向离开棒料尾端所需的最小距离，再在该点不减速地开始侧移。若轴向离料不可省，应把它解释为交接动作的一部分，而不是独立停点。
4. 在相邻路径段的连接处保持速度连续。允许在抓取、夹紧、交接点速度为零；其余连接点用路径混合或统一时间参数化通过，不能为每个路点重新求解并 settle。
5. 如果某处为了实现目标所需的参数改动很小，先怀疑方向错误，重新检查目标函数，不要继续微调增益或加时间。

## 必须输出的四个数

改完后只报这四个数，不写原理：

- 停点总数
- 全程速度归零次数
- 最大方向夹角出现在哪个路点、多少度
- 起步段最短的那一小段是多少毫秒

“停点总数”只数抓取点、夹紧点、交接点这三个允许停点。“速度归零次数”按末端实际速度 `<= 0.02 m/s` 的连续区间计数。“方向夹角”按相邻两帧末端速度向量计算，并报告所在路点；速度为极小值时的方向不可定义，应先用上面三条停点规则排除。起步段最短的一小段要报告其起止路点和毫秒数，格式如 `P1→P2：xxx ms`。
