## 已确认的直接回归原因

原流程在开启 `--lift` 后，应从仿真中读取抬升后的实际工件位置作为抓取目标。草稿把：

```python
pick_at = home.copy()
```

改成了：

```python
pick_at = np.asarray(F.SHAFT_POS, dtype=float).copy()
```

`F.SHAFT_POS` 是台面初始位置，未包含 `LIFT_DZ`。因此开 `--lift` 时，机械臂会向低于抬升后工件的位置下降，挤飞工件。流程随后仍继续执行三爪闭合，导致用户看到“料被挤飞后卡盘直接闭合/穿模”的异常演示。

这不是一个可接受的实验结果，也不能用重新调整阈值解决。

## 其他需要实现模型复核的风险

1. **失败没有成为状态机终止条件**  
   新增了硬失败分类，但没有先验证抓取/可达性再进入搬运和卡盘闭合。实现模型应先定义 `ABORT` 条件；诊断模式若要继续，也必须明确标记为非生产流程。

2. **基准目标与扰动目标混用**  
   新增初始 `dy/dz` 后，实际工件位置改变，但抓取目标固定为名义 `F.SHAFT_POS`。这不能直接称为“扰动鲁棒性”；必须分开三种模式：固定目标抗扰、已知真实位姿重定位、带估计误差重定位。

3. **`roll` 的旋转轴没有定义清楚**  
   圆柱送料轴是世界 x 时，绕自身轴的 roll 不会改变圆柱轴线。当前参数命名和四元数构造没有形成一个明确、可复核的姿态实验。应先定义 yaw/pitch/roll 的坐标系，再实现。

4. **阶段记录可能重复**  
   `tick(tag)` 会记录一次，关键节点附近又显式调用 `record_stage()`。这会产生重复或相邻不同命名的记录，后续统计前必须规定“一个阶段一个快照”。

5. **外力与接触统计边界需要固定**  
   棒料 `qfrc_applied`、接触法向力、20 N 拉拔载荷必须分开。拉拔测试的外力不应被归入交接期隐藏外力；机器人-机床接触也必须按几何类别核对，而不能只按 contype 数字猜测。

6. **JSON 结果不能替代动作回归**  
   即使 JSON 能生成，也不能证明动作未改变。T1 的验收必须同时满足：基准数字/阶段顺序不变、画面没有抓取回归、旧回归通过。

7. **扫描器缺少“基准身份”保护**  
   CSV 需要记录代码版本、参数快照和 case ID；缺少 JSON 或子进程异常时必须是 `ERROR`，不能根据残缺终端文本推断 PASS。
