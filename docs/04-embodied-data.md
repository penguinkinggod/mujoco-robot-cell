# 04 · 具身智能的数据长什么样

## 一句话

**具身智能的训练数据 = 一串 (看到了什么, 自己什么姿态, 做了什么, 想到哪去)。**

`demo_03` 采出来的就是这四样：

```
image  : (240, 240, 320, 3) uint8    <- 相机看到了什么
qpos   : (240, 2)                    <- 两个关节角，即"自己什么姿态"
action : (240, 2)                    <- 每步关节增量，即"做了什么"
goal   : (12, 3)                     <- 每条轨迹的目标点
```

240 个样本、12 条轨迹。**这就是一个能直接喂给 LeRobot 做模仿学习的数据集形状。**

## 为什么"图像 + 动作"这两个必须配对

只存图像：那是个相册，模型学不会"看到这个该怎么做"。
只存动作：那是个录像机的遥控记录，模型不知道为什么要这么动。

**配对才有意义**：模型看到图、输出动作、和真实动作比对、修正。
这叫模仿学习（imitation learning），也叫行为克隆（behavior cloning）。

## `demo_03` 里那个循环，就是全部

```python
for step in range(N_STEP):
    ee = data.site_xpos[SITE]            # 1. 我现在在哪
    err = goal - ee                      # 2. 差多少
    dq = np.linalg.pinv(J) @ err         # 3. 关节该动多少
    data.qpos[:2] += dq                  # 4. 动
    if step % 5 == 0:
        images.append(renderer.render()) # 5. 存：看到什么
        qposs.append(data.qpos[:2])      #    存：什么姿态
        actions.append(dq)               #    存：做了什么
```

**注意第 3 步**：这里的"动作"是人写死的规则算出来的（雅可比伪逆）。
真实机器人上，这一步是**人拿手柄示教**，或者**另一个更聪明的策略**。

这就是"仿真采数据"的价值：不需要真机、不需要人示教，一条规则就能生成几万条轨迹。
LeRobot 那些数据集很大一部分就是这么来的。

## 数据的坑（真实踩过才会知道）

1. **每条轨迹的起点要随机**。全从同一个姿态出发，模型只会学到一个动作。
2. **要有失败样本**。`demo_03` 里第 6 条轨迹失败了（末误差 0.29 m，够不到）。
   这不是 bug，这是好数据——它教会模型"有些目标达不到"。
3. **图像别太大**。320×240 够用了。1080p 的视频采 1 万帧就是几百 GB。
4. **动作要存"增量"还是"绝对位置"，要统一**。混着存，训练会崩。

## 从这里往 AI 走

`demo_03_dataset.npz` 已经是个合法数据集。往下的路：

1. 用 PyTorch 训一个 `图像 -> 动作` 的小网络（一个 CNN + 两个全连接层就够）
2. 训练集/验证集分开，看验证误差
3. 把训练好的模型接回仿真，闭环跑一遍，看能不能到目标

**第 3 步才是关键。** 前两步是"跑通教程"，第 3 步是"真的会了"。

## 你可以试的

`demo_03_camera_dataset.py` 里把 `N_TRAJ = 12` 改成 `50`，重跑。
看 `demo_03_dataset.npz` 从 1.0 MB 变成多大。

**这就是"数据规模"的第一课**：50 条轨迹 ≈ 4 MB，1000 条 ≈ 80 MB。
真实 VLA 模型的数据集是几十 TB。你从这里开始理解为什么"数据是瓶颈"。
