# P5.8.10 有支撑来料偏差保留诊断

完成日期：2026-11-10

## 这轮回答什么

旧的物理扰动入口只移动棒料，V 托架仍固定在名义位置。静置时托架会把棒料推回名义位置，所以“请求偏了”不代表“机械臂抓取前仍然偏着”。

本轮只解决输入设计：在真实重力和实体支撑下，能否让支撑上的来料整体相对机器人与卡盘偏移，并在 600 步静置后保留这个偏差？先做一个 `dy=+3 mm` 单例，不做鲁棒性矩阵，也不调机械臂参数。

## 新增输入方式

新增可选命令行开关 `--support-follows-initial-pose`。开启时，四块静态 V 托架与工件一起按请求的平移和 world-Z yaw 做刚体变换；机器人、卡盘和世界不动。它模拟的是**来料托架/支撑架整体相对工作站错位**，不是把工件放在固定托架里强行偏心。

开关要求同时使用 `--lift`。默认不开启，旧的 nominal 场景和旧扰动命令不变。JSON 会记录支撑坐标系模式和变换的托架几何数量。工件仍有自身质量、真实重力，且 `gravcomp=0`；没有给工件施加外力或力矩。

## 单例设置与结果

| 项目 | 设置 / 结果 |
|---|---:|
| 工件 | 钢圆柱 Ø20 × 80 mm，约 0.1973 kg |
| 夹具 | 90° V 爪；两端静态 V 托架 |
| 送料模式 | M1，使用仿真真实位姿规划；完整无运动学锁送料 |
| 来料误差 | `dy=+3 mm`，`dz=0 mm`，world-Z yaw `0°` |
| 支撑 | 四块托架与来料一起平移；其余世界不动 |
| 静置 | 600 个仿真步，`dt=0.002 s`；最后 100 步评估稳定 |
| 抓取前中心 | `(0.260000, -0.127000, 0.039812) m` |
| 相对 nominal 横向偏差 | `+3.000 mm` |
| 轴线 | `(1.000000, 0.000000, 0.000000)`，与名义轴向一致 |
| 稳定窗口端点最大偏移 | `0.000000751 mm`，低于项目暂定 `0.20 mm` 窗口预算 |
| 左 / 右托架接触 | 各 `100/100` 个窗口样本 |
| 重力 / 工件重力补偿 | `(0, 0, -9.81) m/s²` / `0` |
| 工件外加力 / 力矩 | 无 |

因此，这个支撑坐标系错位设计确实把一个稳定的 `+3 mm` 横向误差带到了抓取前；不是“请求值记下来了，但棒料又回正”。

该单例随后完成了完整物理送料，并通过当前项目判据：最终同轴 `0.723 mm`、轴线倾角 `1.271°`、卡盘接触记录 30、交接 z 峰谷 `3.022 mm`、余量偏心 `1.379 mm`。这次 M1 读取了仿真真值；这个结果只证明该输入案例可执行，不能证明传感器精度、M0 固定目标鲁棒性、普遍成功率或任意来料姿态能力。现有判据仍有项目暂定值，接触穿透也仍被单独记录。

## 判读边界

- 已验证：`dy=+3 mm` 时，工件与支撑一起错位；真实重力下静置后仍保留 `+3.000 mm`，且两侧支撑在最后 100 步持续接触。
- 未验证：工件相对固定托架单独偏移、`dz` 变化和 yaw 变化下的接触稳定性。单元测试检查了平移/yaw 的刚体变换数学，但不是这些姿态的物理稳定性验收。
- 未验证：M0、M1、M2 在同一个真实来料偏差上的配对差异；本轮 M1 使用真值，不含相机或估计噪声。
- 本设计表示一组相对工作站错位的进料支撑，不代表运动输送带，也不代表无限位置/姿态范围。
- 该 PASS 不是重复试验或总体成功率，不说明真实 SO-101 精度；现有接触模型也没有实物标定。

代码入口：`src/diag_feed_chuck.py`，结果 JSON schema v14。定向测试：`tests/test_supported_incoming_pose.py`。原始结果 JSON 在 Git 忽略目录 `_build/p5.8.10-supported-offset/p5810_dy_plus3.json`。

```powershell
  -s tests -p test_supported_incoming_pose.py

```
