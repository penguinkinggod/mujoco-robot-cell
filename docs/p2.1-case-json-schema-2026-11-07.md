# P2.1 实验 JSON 字段规范

首次编写：2026-11-07；验收完成：2026-11-08

## 这张卡解决什么

以前的结果 JSON 有 case ID、部分动作配置和指标，但多个会改变仿真的环境参数没有被一起保存；运行时 NaN 分支也缺少一致的代码版本记录。这样即使看见 PASS/FAIL，也不一定能回答“当时具体用什么工件、控制配置、仿真设置和门槛跑出来的”。

本卡只补齐结果记录，不改变动作、夹具、阈值或通过/失败逻辑。JSON 仍为可选输出。

## 版本号怎么分

| 字段 | 当前值 | 管什么 |
|---|---|---|
| `schema_version` | `4` | 整个结果 JSON 的字段结构 |
| `metric_schema_version` | `1` | 指标定义、单位与测量含义；对应指标字典 v1 |
| `criterion_set_id` | `feed-criteria-v1` | PASS/FAIL 门槛；本卡没有改门槛 |

三者用途不同。以后加字段或调整结构时升级 `schema_version`；改变指标怎么算时升级 `metric_schema_version`；改变门槛时另建 `criterion_set_id`。旧结果不覆盖、不按新门槛悄悄重写。

## 每条结果需要看什么

| 字段 | 人话意思 |
|---|---|
| `case_id`、`random_seed` | 这一次实验的编号和随机种子；当前动作没有随机采样时，种子可为 `null` |
| `inputs.workpiece` | 实际仿真的工件形状、材料、直径、长度、质量、密度和名义初始位置 |
| `inputs.requested_initial_pose` | 运行前要求施加的偏移与滚转 |
| `actual_initial_pose` | 初始静置结束、机械臂开始抓取前的实测位置与四元数；若在到达该阶段前发生运行异常则为 `null` |
| `control_mode` | V 槽、抬升、运动学锁、机床实体碰撞和评价范围等开关 |
| `effective_parameters` | 实际采用的进给、夹爪/夹具、控制器、交接、卡盘和伺服参数；即使参数来自代码默认值，也记录解析后的值 |
| `environment_overrides` | 本程序认识的、实际设置过的物理或诊断环境变量原始字符串值。字段缺失代表使用代码默认值 |
| `model_options.initial` / `model_options.at_result` | 仿真初始和结果时的步长、重力、积分器、求解器等设置 |
| `criteria` | 本次判定实际使用的硬失败与质量门槛 |
| `versions` | Git 提交号、工作树是否有未提交改动、Python/MuJoCo/NumPy/SciPy 与操作系统版本 |
| `stages`、`metrics`、`hard_failures`、`quality_failures` | 阶段过程、测量值和失败原因；按原有语义保留 |

`FEED_CASE_ID`、`FEED_RANDOM_SEED` 单独存入对应字段；`FEED_RESULT_JSON` 是输出位置，不影响物理结果，因此不放进环境覆盖表。环境变量以原始字符串保存，同时 `effective_parameters` 保存程序解析后的实际值，避免只看 `"0"` 或 `"1"` 还要猜单位或默认值。

结果 JSON 的公共补全入口覆盖 `completed`、受控 `aborted` 和运行时 `error` 三种分支。JSON 仍通过 `--json-out` 或 `FEED_RESULT_JSON` 显式启用；不指定时不写文件，终端回归行为不变。

自动测试对受控夹空、运行时 NaN 和完整送料碰撞注入三种 JSON 分支检查共同必填字段；环境覆盖单测验证物理参数被记录，而 case ID、随机种子和输出路径不混入覆盖表。完整回归仍需保持 **10/10**。

## 边界

- 本规范记录当前模型的实际参数，不代表参数是行业标准，也不保证仿真等同实机。
- 有 Git 未提交改动时，JSON 会记录 `git_worktree_dirty=true` 和提交号，但仅凭提交号不能还原未提交代码；正式比较实验应使用干净工作树，或另存对应变更。
- `stages` 仍沿用现有采样点；把六个关键动作节点定义成稳定、易比对的阶段属于下一张 P2.2。

结论：P2.1 已完成。下一张卡是 **P2.2：只补六个关键节点记录**。
