# P1.3 试验有效性与结果分类

日期：2026-11-07

## 这张卡解决什么

`PASS/FAIL` 只说旧判据是否通过，不足以回答“这条结果能不能拿来统计主实验”。例如带运动学锁的旧基线可以满足旧指标，但运动学锁替代了真实接触搬运，不能混进无锁物理送料的成功率。

P1.3 保留原有 `hard_pass`、`quality_pass`、`overall_pass` 和失败列表；新增标签解释**属于哪类实验、数据是否可用于结果统计、结果属于哪种结局**。没有更改动作、夹具和阈值。

## 新标签怎么读

| 字段 | 人话意思 | 当前规则 |
|---|---|---|
| `evaluation_scope` | 这次测试属于哪条赛道 | `primary_physics_feed` 是主实验；`kinematic_lock_reference` 是运动学锁对照；`diagnostic_configuration` 是退出等诊断配置 |
| `trial_data_valid` | 这条记录能不能作为一次有效尝试的结果 | `completed` 或受控 `aborted` 为 `true`；仿真数值异常 `error` 为 `false`。抓空虽然没完成整条路线，仍是有效的失败尝试 |
| `include_in_primary_trial_stats` | 是否进入主实验成功率/失败类别统计 | 仅主实验配置且数据有效时为 `true`；抓空会计入分母并作为失败，带锁对照不计 |
| `physical_task_success` | 是否真正算作主物理任务成功 | 仅主实验配置、完整完成且原 `overall_pass=true` 时为 `true` |
| `outcome_class` | 一句话概括本次结局 | `physical_success`、`quality_fail`、`hard_fail`、`aborted`、`runtime_error`、`reference_pass/fail` 或 `diagnostic_pass/fail` |

主实验配置限定为：无运动学锁、V 槽与抬升路径启用、实体托架存在、机床碰撞几何启用，且使用标准退出动作。其他无锁配置也可能是有用的诊断数据，但不自动混入主实验统计。

这里的“主实验”表示走的是完整物理送料路线，不代表所有工况可以合并成同一个成功率。插入深度、来料偏差、夹具参数等输入不同时，仍要按对应条件分组比较；`include_in_primary_trial_stats=true` 只是说明这条记录有资格进入主实验分析。当前配置记录还不是全部环境参数的完整清单，因此不能只凭这个布尔值就直接汇总大批量结果。

## 样本验收

| 样本 | 原判据 / 执行 | 新分类 | 怎么统计 |
|---|---|---|---|
| D=25 mm 全物理送料 | completed，overall PASS | `primary_physics_feed` / `physical_success` | 纳入主实验，算成功 |
| D=8 mm | completed，hard PASS、quality FAIL（余量偏心约 2.28 mm） | `primary_physics_feed` / `quality_fail` | 纳入主实验，算失败并保留质量原因 |
| `dy=+50 mm` 抓空 | 受控 ABORT，`grasp_empty` | `primary_physics_feed` / `aborted` | 纳入主实验分母，算抓取失败；没有完整质量指标 |
| 历史 `--passthrough` 带锁路径 | 原 `overall_pass=true` | `kinematic_lock_reference` / `reference_pass`；`physical_task_success=false` | 只作参考，不进入主实验成功率 |
| `FEED_RETREAT_AXIAL=0` 诊断 | 全物理路线完成，旧判据 PASS | `diagnostic_configuration` / `diagnostic_pass`；`include_in_primary_trial_stats=false` | 可用于退出动作对照，不与标准主实验混算 |
| 仿真 NaN | ERROR | `runtime_error`；`trial_data_valid=false` | 不当作物理成功/失败；另行统计运行异常 |
| 子进程无 JSON | CSV `ERROR` / `missing_result` | `trial_data_valid=false`，不进入主实验统计 | 不会读到残留的旧 PASS |

针对性 JSON 位于被 `.gitignore` 忽略的 `_build/p13_*.json`。版本字段从 `schema_version=2` 升到 `3`；原来的判据布尔值没有改写。

## 复现与验证

```powershell
$env:PYTHONIOENCODING = "utf-8"
& .venv\Scripts\python.exe -m py_compile src\diag_feed_chuck.py src\diag_feed_insert_sweep.py
$env:FEED_RETREAT_AXIAL = "0"
$env:FEED_RESULT_JSON = (Join-Path (Resolve-Path _build).Path "p13_no_axial_retreat.json")
& .venv\Scripts\python.exe src\diag_feed_chuck.py --v-jaw --lift --no-lock
Remove-Item Env:FEED_RETREAT_AXIAL
Remove-Item Env:FEED_RESULT_JSON
& .venv\Scripts\python.exe verify_all.py
```

通过针对性运行确认正常 PASS、8 mm 质量 FAIL、抓空 ABORT、带锁参考 PASS、退出诊断 PASS、运行时 NaN ERROR 和缺失 JSON 七种分类。退出诊断 JSON 为 `schema_version=3`，`evaluation_scope=diagnostic_configuration`、`include_in_primary_trial_stats=false`。完整回归 `verify_all.py` 为 **9/9**。P1.2 的数值异常和扫描器缺失结果处理仍保持：异常不计入主实验，扫描器不会把旧 JSON 当作新结果。

## 边界

- `trial_data_valid=true` 表示可作为一次尝试的结局数据，不表示整条任务完成，也不表示成功。
- ABORT 纳入尝试分母，避免抓空从成功率里被悄悄删掉。
- 诊断配置与带锁参考可以分析，但不能和主实验合并成一个成功率。
- “主实验”目前只指已声明的仿真配置，不等于真实设备验证，也不等于覆盖任意工件尺寸。
