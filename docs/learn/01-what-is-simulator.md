# 01 · 仿真器到底是什么

## 三件套

MuJoCo（以及所有物理引擎）就三样东西：

| 名字 | 是什么 | 你的直觉类比 |
|---|---|---|
| `model` | **世界的规则说明书**：有哪些物体、多重、多大、关节怎么连、重力多少 | 舞台的图纸 |
| `data` | **世界此刻的状态**：每个关节现在几度、每个物体现在在哪 | 舞台的现场 |
| `mj_step(model, data)` | **把时间推进一小步**（默认 2 毫秒） | 按下播放键一帧 |

代码骨架永远是这三行：

```python
model = mujoco.MjModel.from_xml_string(XML)   # 读说明书
data  = mujoco.MjData(model)                  # 初始化现场
for _ in range(500):
    mujoco.mj_step(model, data)               # 推进 500 步 = 1 秒
```

## 为什么是"描述"而不是"画图"

你写的是 XML，不是建模软件里拖鼠标。比如：

```xml
<body name="box" pos="0 0 1">
  <freejoint/>                                    <!-- 它能自由移动、会掉下来 -->
  <geom type="box" size=".1 .1 .1" rgba=".2 .5 .9 1"/>   <!-- 边长 0.2m 的蓝盒子 -->
</body>
```

`pos="0 0 1"` 意思是"离地 1 米"。所以跑完你会看到：

```
box 落地后的高度 z = 0.0999
```

落到 0.1 m 就停了——因为盒子半高 0.1 m，贴着地面。**这就是仿真在干活。**

## `demo_00` 里唯一需要记住的一句

> 你只描述"世界是什么样"和"物理规律"，**不描述"它该怎么动"**。
> 怎么动是引擎算出来的。

这条分界线，就是"做动画"和"做仿真"的根本区别：
- 做动画：你写每一帧的位置。
- 做仿真：你写世界，让物理决定下一帧。

`demo_02` 里我直接改 `qpos`（关节角），那是**退回了做动画**——所以它穿过障碍物也不管。
`demo_04` 我只改 `ctrl`（目标值），交给引擎算，那才是真仿真。
