# 06 · 为什么"数值算对了"机械臂还会错

> 这是整个仓库最重要的一篇笔记。
> 它回答一个问题：IK 残差只有 0.5 mm，为什么实际执行差了 38 mm？

## 一次真实的诊断

目标：让夹爪中心到达 z = 0.03 m（方块中心附近）。

| 层 | 测出来 | 说明 |
|---|---|---|
| 1. 数学误差 | **0.0005 m** | IK 残差，可忽略 |
| 2. 控制误差 | **0.038 m** | 伺服实际到达和指令差 55 倍 |
| 3. 物理约束 | **撞桌面** | 夹爪穿进桌面 19.8 mm |
| 4. 根因 | **几何冲突** | 指垫比方块长 12.6 mm |

**第 1 层没问题，第 2、3、4 层全是物理世界的锅。**

## 第 2 层：位置伺服的稳态误差

Panda 的执行器是位置伺服：

```
输出力矩 = kp × (目标角度 - 实际角度) - kd × 速度
```

系统最终停在"伺服力矩 = 重力力矩"的位置，所以必然有残差：

```
稳态误差 ≈ 重力载荷 / kp
```

实测（关节 2）：载荷 40.42 Nm，kp=4500，理论误差 0.00898 rad，实际 0.00701 rad。**公式成立。**

这不是 bug，是这类控制器的固有特性。真实 Panda 出厂自带重力补偿，就是为了消掉它。

**修法（三选一）：**
1. 提高 kp（伺服调硬，代价是容易振荡）
2. 加重力前馈（demo_01 里那句 `u += qfrc_bias` 就是）
3. 加积分项 I（PI 控制，靠时间累积消差）

## 第 3 层：撞桌面

执行时夹爪确实"到位了"——但到位的位置在桌面**里面**。

实测：夹爪子树最低点 z = +0.0026 m，接触 13 个点，法向力最大 19.34 N。手臂被桌面顶住，j6 关节想要 325 Nm 去纠偏，上限只有 12 Nm，**差 27 倍**，于是整个姿态被拉歪。

**这不是"代码写错了"，是任务本身在物理上做不到。**

## 第 4 层：最隐蔽的根因——指垫比方块长

这是整个诊断里最值钱的发现。

之前代码写 `FINGER_OFFSET = 0.0584`，注释说这是"夹爪抓取中心"。**量出来发现它是错的：**

| 位置 | 相对 hand 的偏移 |
|---|---|
| 指根（finger body 原点） | 0.0584 m ← 之前用的 |
| 指垫最低点 | 0.1140 m |
| **指垫中心** | **0.0862 m ← 该用的** |

指垫长度 **55.6 mm**，方块高度只有 **43 mm**。

所以"指垫中心对齐方块中心"这个目标，在几何上**必然**让指垫下端插进桌面 6.3 mm。跟参数调不调、IK 准不准都没关系——**这个任务在当前几何下无解。**

demo_04 之前"看起来成功"只是运气：方块挡住了指垫，接触力被 solver 吃掉，没把方块撞飞。真实机器人上这就是"夹爪撞工作台"，触发碰撞报警停机。

## 修法

```
指垫半长 27.8 mm + 安全间隙 4 mm = 抓取中心最低 z = 0.0318 m
```

并且 `FINGER_OFFSET` 改成真正的指垫中心 0.0862。

改完实测：夹爪离桌面 **10.1 mm** 间隙，方块抬高 **0.195 m**（原 0.157 m），可达性检查三段全 OK。

## 所以"数值约束为什么会错"

> **因为数值约束描述的是理想世界，执行发生在有几何、有摩擦、有力矩上限的真实世界。**

四类错误的性质完全不同：

| 类型 | 例子 | 是不是 bug | 修法 |
|---|---|---|---|
| 算法错 | IK 不收敛 | 是 | 改算法 |
| 模型错 | 忘加摩擦 | 是 | 补参数 |
| **物理限制** | 撞桌面、力矩饱和 | **不是** | 改任务 |
| **控制固有误差** | 稳态误差 8 mm | **不是** | 加前馈/积分 |

**遇到"抓不住"，第一反应不该是改代码，是先分清是哪一类。** 这就是 `reachability.py` 存在的意义：执行前把"物理上做不到"的拦下来，别浪费时间去调一个无解的任务。

## 可达性检查器查什么

`reachability.py` 的 `check_grasp_pose()` 每次检查六件事：

1. **关节限位**——目标角度是否超出范围，离限位还有多少余量
2. **力矩饱和**——托住这个姿势要多少力矩，占上限的百分比
3. **碰撞**——夹爪子树最低点离桌面多少
4. **接触检测**——夹爪有没有和不该碰的东西接触（要抓的方块除外）
5. **伺服误差预测**——按 载荷/kp 预估稳态误差
6. **IK 残差**——理想位置和目标的差

任何一条不过就报"不可达"，并告诉你**是哪一条、差多少**。

## 踩过的坑（真实记录）

写检查器时我自己也踩了两个：

1. **误报自接触**：夹爪闭合到 0 时左右指贴在一起，产生几十个接触点。第一版没排除，导致"夹爪和 geom80 有 12 个接触点"的假警报。修法：同属夹爪子树的接触不算。
2. **误报"抓到目标"**：夹爪碰到要抓的方块本来是任务目的，第一版把它算成"接触异物"。修法：加 `expected_contacts` 参数，白名单放行。

**工具本身也要被诊断、被修正。** 这不是失败，这是写代码的正常节奏。

## 你可以试的

1. 打开 `check_reach.py`，把 `XY = (0.55, 0.05)` 改成 `(0.75, 0.05)`——更远的位置。
   看扫描表里"力矩占用"是不是涨了，最低安全高度是不是变了。
2. 改成 `(0.30, 0.05)`——更近。看会不会报"关节贴限位"。
3. 把 `CUBE_HALF` 改成 `0.035`（7 cm 方块，比指垫长），重跑。
   看指垫终于"短于"物体之后，碰撞报告会不会消失。

**这三个实验做完，你就真正理解"工作空间"这个词了**——它不是画在纸上的一个圆，是由力矩、限位、几何共同决定的、可以用数字量出来的东西。
