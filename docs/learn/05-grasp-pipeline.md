# 05 · 抓取流程：真实产线上的标准五段式

## 为什么不是"直接过去抓"

新手的第一反应是：算出方块位置 → 让夹爪直接过去 → 夹住。
**真实机器人从来不这么干**，因为：

- 直线过去会撞桌子、撞其他物体
- 到得太快，伺服跟不上，会超调
- 夹爪歪着下去，夹不住

所以标准做法是**分段 + 每段平滑过渡**。

## 五段

| 段 | 动作 | 为什么 |
|---|---|---|
| `move` | 移到方块**正上方 22 cm** | 先到高空，避开桌面上一切东西 |
| `down` | 竖直下降到抓取高度 | 只走 z 方向，不横向蹭 |
| `close` | 夹爪闭合 | 停住不动，只动夹爪 |
| `lift` | 竖直抬起 20 cm | 先抬起来，再横移 |
| `hold` | 保持 | 检查有没有滑落 |

这就是工业上说的 **approach → descend → grasp → lift → verify**。
你以后看任何机械臂抓取视频，都能拆成这五段。

## 平滑过渡：为什么用余弦

```python
a = (i + 1) / n
a = 0.5 - 0.5 * np.cos(np.pi * a)      # 余弦缓动
data.ctrl[:7] = (1 - a) * q_from + a * q_to
```

`a` 从 0 到 1，但**不是匀速**：开头慢、中间快、结尾慢。

用匀速（`a = i/n`）会怎样？起步瞬间速度从 0 突跳到额定值，加速度无穷大，
真实电机要么丢步、要么触发过流保护。仿真里看不出来（因为伺服会兜住），
但真机上一定出问题。

**这类"仿真里没事、真机上炸"的差异，就是 sim-to-real 的核心难点。**

## 成败怎么判定

不是"看起来像抓到了"，是量出来的：

```python
cube_lift = data.xpos[cube][2] - CUBE_Z      # 方块被抬高多少
grip_width = |left_finger - right_finger|    # 夹爪开口
ok = cube_lift > 0.05
```

实际输出：

```
方块被抬高   : 0.157 m
夹爪最终开口 : 0.042 m（方块宽 0.043 m）
判定         : 抓起来了 OK
```

夹爪停在 0.042 m，比方块 0.043 m 略小——**这是"夹紧"的物理证据**：
夹爪想闭合到 0，被方块挡住了，停在被夹物体的宽度上。

**养成这个习惯：每个 demo 都要有量化判定。** 靠肉眼看 GIF 说"成功了"，
是外行做法，也骗不了自己。

## 我踩过的三个坑（真实记录）

1. **只解位置不解姿态** → 夹爪歪着下去，末端到了但夹不住。
   修法：把姿态误差也放进 IK，6 维一起解。
2. **头灯把场景打爆** → 渲染出来一片惨白，看不出结构。
   修法：`spec.visual.headlight.active = False`，自己加两盏方向光。
3. **摩擦系数给小了** → 夹住了，一抬就滑。
   修法：`cg.friction = [1.5, 0.08, 0.002]`。

这三个都不是"理论问题"，是**跑一次、看一眼、改一行**解决的。
你现在的能力刚好够做这件事——因为报错和异常画面会告诉你哪里不对。

## 你可以试的

1. 把 `CUBE_HALF = 0.0215` 改成 `0.035`（更大的方块），重跑。
   看夹爪开口还够不够（张开只有 0.08 m）。
2. 把 `cg.mass = 0.04` 改成 `0.5`（5 kg 重物），重跑。
   看还抬得起来吗——Panda 的负载上限是 3 kg。
3. 把 `GRASP_Z` 再降 0.01 m，重跑。
   看会不会撞桌面。

**这三个改动，就是"参数敏感性分析"**，工程报告里最值钱的那部分。
