# 项目路线图：变尺寸棒料的机床上下料与协同参数优化

更新：2026-11-10。里程碑按仓库当前证据重排；具体任务与状态见 [项目任务总账](project-taskbook.md)。

长期方向是“工件参数 → 参数化夹具候选 → 机器人完整上料与卡盘交接 → 仿真评测/参数搜索”，可逐步连接 SW→MC 和后续 AI。本文记录机械臂当前物理主线；项目伞形方向、论文候选、导师资源和投稿阶段闸门见[论文路线图](paper-roadmap.md)。论文第一切口尚未锁定，不能把支撑自定心这个单项发现当成整个项目主题。真实重力下受支撑 nominal 已完成，当前继续核查有效偏差下的过程差异。

## 我对截图方案的判断

截图提醒的几件事是对的：只展示一个成功视频不够；必须有固定基线、逐项消融、失败案例和可复现数据。截图给出的论文档次、成功率数字和“高引用”预期不能当成计划指标，必须等实验做完再判断。

建议把 **A“机床接触式装夹”作为研究问题，把 C“标准化测试集”作为研究交付方式**。本项目区别于一般抓取的具体场景是：SO-101 抓取圆柱棒料、把它送进三爪卡盘、让卡盘接管，并以夹持、同轴误差、余量偏心、交接位移和动作时间评价整个过程。不要宣称“第一个工业装配基准”；已有机器人操作基准和装配基准，项目需要靠“机床卡盘交接任务、物理分层指标和可复现实验范围”说明自己的具体价值。

截图里的 **B“仿真到真机”先列为条件分支**。目前没有实体机械臂和测量数据，仿真结果无法单独证明真机迁移。**BC、ACT、Diffusion Policy、SAC 横向大比拼也不进入近期主线**：当前尚未定义统一的观测、动作接口和训练数据，先解决抓取、交接和判据，比较传统基线与一个针对失败原因的改进即可。将来确有硬件，再增加仿真参数标定和真机对照；没有硬件时不把它说成 Sim-to-Real 成果。

## 和 SW→MC 项目的关系

我只按本地 README 做表层判断：SW→MC 接收结构化零件参数或 STEP，输出 SolidWorks/STEP、分层 DXF、工艺 JSON、NC 和工程图；Mastercam 环节包含人工确认。README 也明确写出没有刀路仿真、碰撞检查和实切验证。因此它是参数化 CAD/CAM 自动化原型，不能直接称为已验证的可加工生产系统。

它和机械臂项目有结合价值，关键不是把两份源码硬塞进一个目录，而是定义**同一个工件任务数据**：零件标识、毛坯直径/长度/质量、成品外形参数、坐标方向、卡盘夹持/插入条件和来料状态。SW→MC 侧根据成品参数生成模型和工艺包；机械臂仿真侧读取毛坯和装夹参数，验证抓取与卡盘交接。毛坯和车削后的成品形状必须分开表示，不能把“成品模型”直接当作机械臂要抓的原材料。

建议先做一个共同样例的纵向切片，再扩成批量：选一个 SW→MC 支持的轴类零件，明确它对应的圆柱毛坯和卡盘基准；由版本化 JSON 同时生成 SW→MC 输入和机械臂 case；检查尺寸、单位、轴向、卡盘端方向一致。若 SW→MC 当前参数文件没有明确的毛坯字段，就在共同任务格式里新增，不猜测或从成品外形反推毛坯。两边仍可保留独立仓库，通过 schema 版本和样例数据连接，最后用一个项目总览页串起来。

**适合尝试微调的 AI 任务：** 把中文零件/加工需求转换成 SW→MC 的受约束参数 JSON。SW→MC README 已描述 NLP → JSON 输入路径，因此先做基线比较：现有规则/解析方式、基础模型直接输出、微调后模型；所有输出都过 schema、尺寸关系和下游模型生成验证。模型不直接输出 NC，也不绕过人工确认。机械臂端的参数筛选先用网格或随机搜索；有足够、标注可信的仿真数据后，再考虑训练参数预测代理模型。策略微调/强化学习是另一个任务，当前不需要。

## 项目问题

**暂定题目：** 面向小批量机加工上下料的机器人仿真评测与参数优化。

**核心问题：** 对明确范围内的圆柱棒料、来料位置/姿态误差和卡盘入口条件，当前 SO-101 与 V 槽方案会在哪些条件下抓取或交接失败？针对失败原因调整抓取接近或有限夹具/送料参数后，能否在相同测试条件与仿真预算下，比固定方案提高完整任务的成功率或加工余量表现？

研究结果必须限定在已声明的工件、夹具、误差范围和 MuJoCo 接触参数内。“最优”只代表这些候选和样本范围内的最佳方案，不等于通用夹爪或真机工艺标准。

- P5.8.13 已在 nominal M1 下诊断抓取前运动：接近和侧向进入阶段均无机器人—工件接触，但计划姿态变化、接近分段停走和末端跟踪差均可能影响观感；还未区分主因或调参。P5.8.14 记录到最大棒料中心位移 `3.591 mm` 早于卡盘首碰，当时机器人 V 爪和导套都接触；夹紧与稳定期间机器人仍接触工件。本轮也只作诊断，没有调参。

## 物理状态要说清楚

“在空间任意摆放的工件”如果没有支撑且开启重力，会持续下落；这时任务是抓取运动中的落体，属于拦截问题。当前 `gravcomp=1` 则让工件在无接触时保持位置，便于单独看碰撞如何推料，但它不能代表真实重力。主线推荐先做更贴近流水线的**有支撑来料 + 真实重力**，在托架/料台允许的有限位置和姿态范围内测试。若以后要研究空中拦截，再单独开一条任务线，不要把两种设置的数据混在同一成功率里。

抓取位移也按阶段解释：接近和闭爪期间的位移是重要诊断量，不自动等同失败；它若造成漏抓、接触丢失、超出卡盘捕获余量或最终余量偏心超限，就应由相应任务判据判失败。夹爪是否稳持、卡盘能否接管，是两个独立验收点。
